# Health Data Operability Maturity Assessment

[Open the interactive assessment](index.html)

## About this resource

The **Health Data Operability Maturity Assessment** is an interactive toolkit for assessing whether important data remains interpretable, usable and fit for purpose as it moves across systems, organisations, transformations and time.

It is designed to support structured assessment and facilitated discussion rather than to produce a simplistic overall score.

The assessment emphasises cumulative maturity, evidence, confidence and the constraining effect of weak dimensions.

## What it helps you do

Use the toolkit to:

- define the scope of an assessment;
- identify priority data;
- assess six operability dimensions;
- separate documented practice from demonstrated practice;
- record evidence, confidence and notes;
- identify anti-patterns;
- compare claimed and evidenced maturity;
- identify the constraining dimension;
- agree priorities and next steps;
- print an assessment report;
- export an assessment; and
- export responses as CSV.

## Starting an assessment

Select **Start an assessment** and complete the required scope information.

Required fields include:

- assessment title;
- organisation or service;
- one to eight priority data items; and
- assessment date.

Optional information includes facilitator, participants and contextual notes.

The assessment can also be used for a workshop or partnership context.

## How to answer

The toolkit separates capability that is merely **documented** from capability that is actually practised.

The maturity levels are cumulative. A higher level should therefore only be selected where the lower-level capabilities are also present.

Use **Not known** where evidence is insufficient rather than guessing.

## Working through the dimensions

For each dimension:

1. review the maturity statements;
2. select the level best supported by evidence;
3. record whether relevant practices are documented;
4. add evidence;
5. record confidence;
6. add explanatory notes where useful; and
7. respond to any anti-pattern or inconsistency flags.

The toolkit may ask for a rationale where the selected level appears to conflict with another answer.

## Reviewing results

The results view includes:

- the maturity profile;
- the constraining dimension;
- claimed versus evidenced maturity;
- assessment flags;
- implications for automated use;
- anti-pattern review;
- next steps; and
- dimension notes and confidence.

The constraining dimension is particularly important because overall operability can be limited by a weak capability even when other dimensions are mature.

## Saving and reopening

The toolkit supports reopening a saved assessment on the same device and opening an exported assessment file.

Use **Export assessment** if the assessment needs to be retained or transferred.

## Reporting and export

Available outputs include:

- printable report;
- exported assessment;
- response CSV; and
- evidence and notes recorded within the assessment.

## Interpretation

The toolkit is intended to support evidence-led maturity discussion.

It should not be used to create false precision by averaging unlike capabilities into a single score.

A documented policy is not the same as demonstrated operational practice, and a claimed level should not be treated as evidenced unless the supporting material is available.

## Technical notes

The interactive HTML resource is self-contained and intended for static hosting. It uses standard HTML, embedded CSS and vanilla JavaScript, so no application server or build process is required.

When deployed in the Agile Health Informatics GitHub Pages site, keep this Markdown file in the same repository directory as its corresponding HTML file so the relative link above remains valid.
