1. Executive judgement

The difficult semantic decision is rarely “which code system?” It is deciding what kind of meaning must be preserved.

Clinical terminologies, classifications and product dictionaries are designed for different jobs. A terminology can preserve rich clinical distinctions, a classification can intentionally collapse them for comparison, and a value set can constrain what is appropriate in one context. Mature semantic architecture lets those artefacts coexist while governing every mapping between them.

Green: explicit semantic rolesAmber: mappings and subsets need governanceAmber–Red: codes without version, context or provenance

Terminology is not classification

Detailed clinical recording and statistical aggregation make different trade-offs. Mapping from one to the other is a purposeful transformation and may discard distinctions by design.

A code system is not a value set

Code systems define concepts. Value sets select which codes may be used in a specific context. Treating them as interchangeable creates drift.

Version is part of meaning

Longitudinal records must retain which release, subset and mapping were in force when data was created or transformed.

9. Semantic anti-patterns

Semantic debt is usually created by decisions that look locally reasonable.

The message validates

Conformance equals meaning

Structural validation is mistaken for semantic equivalence.

Close enough

Approximate mapping

A convenient target code is chosen without residual mismatch or confidence.

Everyone uses SNOMED

Ungoverned vocabulary choice

An entire terminology is allowed where a governed value set was required.

One code column

Systemless coding

Codes are stored without canonical system identity or version.

Make history current

Retrospective recoding

Old codes are silently replaced with modern ones.

Translate the label

Linguistic flattening

Literal text translation is assumed to preserve clinical meaning.

One canonical vocabulary

Semantic monoculture

Specialist or regulatory semantics are flattened beyond the chosen vocabulary's scope.

Mapping lives in ETL

Hidden mediation

Semantic knowledge survives only as unversioned code or supplier configuration.

Classification at source

Premature information loss

Coarse reporting categories replace richer clinical capture.

11. Recommended actions

Treat semantics as shared infrastructure.

Separate code systems from value sets

Give each governed subset a canonical identity, owner, version and change process.

Version mappings

Record direction, purpose, source and target versions, equivalence and review evidence.

Operate a terminology service

Support lookup, expansion, validation, translation and historical resolution as reusable services.

Preserve source semantics

Keep original codes and versions when deriving classifications or analytical representations.

Link metadata and terminology

Connect data definitions to code systems, value sets, units and model bindings.

Measure semantic debt

Track local codes, approximate mappings, divergent value sets and unversioned transformations.

13. Limitations

What this navigator does not claim.

Terminology adoption varies by jurisdiction and speciality. The catalogue is selective, not exhaustive. Licensing and national implementation requirements must be checked before deployment. Exact code-system releases, value sets and mappings should always be resolved from the authoritative publisher or terminology service at implementation time.
