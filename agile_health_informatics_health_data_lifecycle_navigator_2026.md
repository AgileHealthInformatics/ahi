# Health Data Lifecycle Navigator

[Open the interactive navigator](agile_health_informatics_health_data_lifecycle_navigator_2026.html)

## About this resource

The **Health Data Lifecycle Navigator** is an interactive professional resource for preserving the **operability, meaning, provenance and trustworthiness of health data across its lifecycle**.

Its central idea is that data operability must be maintained as data moves between purposes, systems, organisations, transformations and time. It is not automatically achieved by using an interface standard.

## What it helps you do

Use the navigator to:

- identify lifecycle obligations at a particular point in the data journey;
- start from the work being attempted rather than from a technology;
- examine operational and change/governance lifecycle phases;
- identify the contextual information that must travel with data;
- explore relevant standards;
- assess maturity in preserving operability;
- recognise lifecycle decisions that create semantic debt; and
- review the twelve lifecycle obligations in one view.

## How to use the navigator

### 1. Identify where the data is now

Use the lifecycle view to identify the current phase and the obligations that apply at that point.

### 2. State what you are doing

Use **What are you doing?** to select the activity or purpose driving the current decision.

### 3. Search and filter

Available controls include:

- **Search phases, risks or standards**;
- **Lifecycle ring**;
- **What are you doing?**; and
- lifecycle phase selection.

The lifecycle ring distinguishes **change and governance** from **operational** phases.

### 4. Inspect the contextual package

The navigator emphasises that the data item alone is not enough. It highlights the need to preserve contextual information such as:

- provenance;
- method;
- intent;
- constraints;
- quality;
- lawful basis;
- lineage; and
- representation.

### 5. Explore standards

Use the standards search to identify resources that help with a particular lifecycle concern.

No single standard is presented as covering the whole lifecycle.

### 6. Review maturity

The maturity section can be used to consider how well an organisation preserves operability as data moves and changes.

### 7. Use the twelve-obligation view

The consolidated view brings the principal lifecycle obligations together so that gaps are easier to see.

## Interpretation

The navigator distinguishes storing data from preserving its meaning and future usability.

A technically successful transfer or migration should therefore not be interpreted as evidence that semantics, provenance, quality and contextual constraints have survived.

The resource is a professional guide and does not replace statutory retention requirements, information-governance policy or authoritative standards.

## Technical notes

The interactive HTML resource is self-contained and intended for static hosting. It uses standard HTML, embedded CSS and vanilla JavaScript, so no application server or build process is required.

When deployed in the Agile Health Informatics GitHub Pages site, keep this Markdown file in the same repository directory as its corresponding HTML file so the relative link above remains valid.
